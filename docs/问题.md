# Round-05：第一层子 agent 被错误记录为用户线程，仍泄漏到 WebUI 侧边栏（2026-08-21，未解决）

## 结论

`codex-mobile-re@0.1.101` 已能过滤元数据正确的 `thread_source: "subagent"` 会话，但未解决真实两层代理工作流中的第一层子 agent 泄漏。

根因不在页面刷新或 PWA 缓存，也不是 `agent_type: worker` 参数失效；而是主线程创建第一层子 agent 时，落盘的会话元数据错误地把它写成顶层用户会话：

- `thread_source: "user"`；
- `parent_thread_id: null`；
- `originator: "codex_exec"`。

WebUI 的过滤器只根据 `thread_source` 以 `subagent` 开头的会话 id 排除侧边栏条目，因此无法识别这些已丢失父子关系的第一层子 agent。

## 真实拓扑与实测数据

用户确认的真实执行关系是：

```text
主线程
└── 子 agent（agent_type: worker；本应隐藏）
    └── 孙 agent（由子 agent 调用 spawn_agent；本应隐藏）
```

2026-08-21 现场数据中，以下两条是用户确认的第一层子 agent，但元数据均被记录为 `thread_source: "user"`，因此出现在侧边栏：

| 第一层子 agent 线程 | 会话文件时间（北京时间） | 被错误记录的来源 |
|---|---:|---|
| `01a021a2-dd8b-71f0-816c-812a96739320` | 08:05 | `thread_source=user`，`originator=codex_exec` |
| `01a021a7-a3a9-7c33-a7bc-5fc7d8e09e44` | 08:10 | `thread_source=user`，`originator=codex_exec` |

这两条线程继续派生的孙 agent 则带有正确元数据，例如：

| 孙 agent 线程 | `parent_thread_id` | `thread_source` | 侧边栏结果 |
|---|---|---|---|
| `01a021a3-474c-7fb0-ae36-08e12fa244c1` | `01a021a2-dd8b-71f0-816c-812a96739320` | `subagent` | 已过滤 |
| `01a021a7-d624-7861-ab73-117c680edcce` | `01a021a7-a3a9-7c33-a7bc-5fc7d8e09e44` | `subagent` | 已过滤 |

因此，当前过滤逻辑不是完全失效，而是只覆盖“子 agent → 孙 agent”这一步；“主线程 → 子 agent”这一步的会话身份已经在上游创建时丢失。

## 为什么现有 0.1.101 修复无法处理

0.1.101 在 `thread/list` 返回前主动扫描 session 文件，并排除 tracker 识别出的 `thread_source=subagent` 的线程 id。该实现对上表的孙 agent 有效。

第一层子 agent 的 session 文件却与普通用户通过 CLI 发起的会话没有可用的结构化区别。仅从提示词中包含 `agent_type: worker` 推断身份不可靠，也会误隐藏用户手动执行的普通 CLI 任务。因此，不能通过扩大 WebUI 的文本匹配来安全修复。

## 正确修复位置与验收

修复必须发生在创建第一层子 agent 的 spawn/bridge 链路：

1. 创建的 rollout `session_meta` 必须写入 `thread_source: "subagent"`；
2. 必须写入真实 `parent_thread_id`；
3. 子线程自身 id 与父线程 id 必须保持区分；
4. WebUI 再按结构化元数据过滤，而不是解析提示词。

修复后必须进行真实两层回归，而不是只检查包版本或单层 spawn：

```text
主线程 → 子 agent（worker）→ 孙 agent
```

验收标准：

- 子 agent 和孙 agent 均不出现在 WebUI 侧边栏；
- 主线程仍出现，且可正常打开；
- 两层会话的 `session_meta` 均含正确的 `thread_source=subagent` 与 `parent_thread_id`；
- 不误隐藏用户手动启动的普通 CLI 会话。

## 当前状态

- `codex-mobile-re`：运行 `0.1.101`，registry 最新亦为 `0.1.101`；
- `codexapp.service`：运行正常；
- 前端未刷新时已观察到问题，故不能归因于刷新后的旧列表合并；
- 未修改生产代码、服务配置或会话数据；
- 下一步：定位第一层 `spawn_agent` 到 `codex_exec` 会话创建之间丢失 `thread_source` / `parent_thread_id` 的具体桥接层，然后修复并完成上述两层回归。

## 结论（2026-08-21 更新：round-05 已解决）

- 根因与该文档一致：`codexapp` 是单一 `codex app-server` 的纯 RPC 代理，第一层 worker 由 codex 引擎写成普通用户会话（`thread_source=user`、`parent_thread_id` 缺失、`originator=codex_exec`），在文件层面与真实用户线程几乎不可区分；唯一结构化信号是孙 agent 的 `thread_source=subagent` 且其 `parent_thread_id` 回指该 worker。
- 由于无法（也无需）修改 codex 的会话写入，改为在 `thread/list` 过滤时补充可辨识的结构化边界：
  - `externalSessionTracker.ts`：`TrackedSession` 新增 `parentThreadId` 并在 `updateSessionMeta` 解析 `parent_thread_id`；新增 `getUserFacingSubagentThreadIds()`，返回 `thread_source=subagent` 会话 ∪（`originator=codex_exec` 且被某 subagent 记为父）的会话。
  - `codexAppServerBridge.ts`：`thread/list` 过滤改用 `getUserFacingSubagentThreadIds()`。
- 验收（两层回归，均通过真实/单测验证）：
  - worker 与孙 agent 均不出现在侧边栏；主线程仍出现且可正常打开；
  - 真实用户线程（`vscode`/`codex-tui`，非 `codex_exec`）即使直接 spawn 了 subagent，其本身不会被误隐藏，被 spawn 的子 agent 仍按 `thread_source=subagent` 隐藏；
  - 两层会话的 `session_meta` 结构事实不变，过滤基于可辨识元数据，不解析提示词。
- 测试：`externalSessionTracker.test.ts` 17/17、`codexAppServerBridge.inlinePayload.test.ts` 28/28、`vue-tsc --noEmit` 通过；手测文档 `tests/thread-loading-state/subagent-threads-filtered-from-sidebar.md` 已补两层用例。

# Round-06：review-pane 弹窗化 + 长 diff 滚动到底（2026-08-21）

## 背景

审查工作树面板（`review-pane`）曾在退出后仍有残留界面、且唯一的路由退出途径在移动端被遮挡；变更金字塔要求先确认 `review-pane` 是否已正确弹窗化。确认其确为 Modal 后，开展弹窗化与滚动约束改造。

## 问题

- `review-pane` 原非标准弹窗，无半透明遮罩，移动端按全屏面板（`inset:0`）处理；
- `review-pane-diff` 长内容可滚动，但最底部被遮挡，无法滚到真正的最后一行。

## 修复

`src/components/content/ReviewPane.vue`：

- 弹窗化：`<Teleport to="body">` + `review-pane-backdrop` 遮罩，桌面为居中卡片（`height: min(88dvh,100%)`，`width: min(72rem,100%)`），移动端为底部抽屉（`height: 90dvh`，`rounded-t-3xl`），点击遮罩可关闭；
- 滚动约束：`.review-pane-main` 用 `grid-cols-[文件列表_0.5rem_diff]` + `grid-rows-[minmax(0,1fr)]` + `overflow-hidden`，让 `.review-pane-diff` 成为高度受限的正确滚动容器，保证长 diff 能滚到真正底部且底部不被遮挡。

相关挂载：`src/App.vue` 用 `v-if="isReviewPaneOpen && ..."` 挂载 ReviewPane 并通过 `@close` 关闭。

## 验证

`D:\code\codex` 线程工作区新增未跟踪长文件（`scroll-verify-sample.md`，约 360 行新增），真实 diff 内容在两个视口均滚动到底：

- 移动端 375×812：`scrollHeight 8826 / clientHeight 523`，`reachedBottom == maxScroll 8303`，`visibleAtBottom: true`；
- 截图：`output/playwright/review-scroll-desktop.png`、`review-scroll-mobile.png`。
