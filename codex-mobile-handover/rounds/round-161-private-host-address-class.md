## 二、为什么这是「执行既有规则」而不是「扩范围」

round-160 §六.⑥ 把「主机名 / 内网 IP / 端口」判为闸门范围外，理由写的是「§5.4 只管路径」。
这个理由**与规范原文不符**：

1. §5.4 末句写明判定线 —— 「**真正的判定线是「能不能标识本机 / 本用户 / 这份工作副本」**」。
   这条判定线**不是路径专属**，它是**按「信息能否定位到本机」**立的。
2. §5.4 的立论是**可移植性**：「本项目跨机器 / 跨平台运行，换机后路径必然不同」。
   而 tailnet 地址（`100.64.0.0/10` 段）**换机后同样不同** —— 换一台机器 / 换一个人，该地址必然失效。

⇒ 属「规则已覆盖、闸门缺类」的形态，与 round-159 §六.7（盘符家目录骨架：§5.4 明文点名、闸门却没类）**同源**。
本轮改的是**类定义**，不是「规则条文之外的加码」。

## 四、修复

### 4.1 闸门新增类（`scripts/check-handover-desensitization.cjs`）

```
{ id: '私网/Tailscale 主机地址',
  re: /(?<![\w.-])(?:100\.(?:6[4-9]|[7-9]\d|1[01]\d|12[0-7])|10\.\d{1,3}|172\.(?:1[6-9]|2\d|3[01])|192\.168)\.\d{1,3}\.\d{1,3}(?!\d)(?!\/\d)/g }
```

三个关键决策：

1. **分支各自吃满 4 段**（`100.64-127.x.x` / `10.x.x.x` / `172.16-31.x.x` / `192.168.x.x`）。
   反例即**本类第一版**：`10` 分支只写成裸 `10`（后两段靠共享后缀）⇒ 只吃到 **3 段**，闸门把 4 段地址报成 3 段。这个 bug 一直没被发现，**直到本文档拿一个 4 段私网示例举例时，闸门把它自己拦了下来**。修法见 `fa846b59`：给该分支补上自己的第 1 段（`10\.\d{1,3}`），并加 `--selftest` 把行为钉死 —— 这类 bug **在语料上零命中、实跑永远不露头**，只能靠定向用例守住。
2. **`(?!\/\d)` 排掉 CIDR 网段声明** —— 这一条是**必须**的：不排则 5 处 `100.64.0.0/10` 全部变误报（这正是 §3.1 里那 5 处）。
3. **前置环视不复用 `NB`** —— 现有各类的 `NB = (?<![A-Za-z0-9._:+\/-])` 把 `/` 与 `:` 也算作「前驱」，那样 `http://100.…` 的匹配会被 `/` 挡掉，**真实地址反而测不到**。本类改用 `(?<![\w.-])`。

放行项（写进脚本头注释的「有意不拦」）：`127.0.0.1` / `localhost` / `0.0.0.0`（通用写法 —— §5.4 **自己的代理示例**就用 `127.0.0.1:10808`）、CIDR 网段声明。

## 六、诚实边界

1. **零产品代码改动** ⇒ 本轮**未跑** `vue-tsc` / 全量单测 / `vite build`（基线仍以 round-157 的 **998 例 / 87 文件**为准）。改动脚本用 `node --check` 与自身退出码跑通。
2. **主机名仍不在闸门范围**（含 `.local`、`*.ts.net`）：**实测 3/3 误报**（撞 localStorage 键名里的 `.local.`）⇒ 要收得先有**形式可区分**的判据，本轮不建类。
3. **IPv6 主机地址未建类**：语料里只有 CIDR 形态（`fd7a:115c:a1e0::/48`），**没有真实 IPv6 主机地址**；IPv6 正则极易误伤 CIDR（`fd7a:115c:a1e0::` 与 `/48` 的分界很难只靠正则判）。⇒ **尚未做**，不是有意不做。
4. **端口号仍不校验**：`:4173` 之类换机也未必相同，但 `4173` 是本仓**固定 dev 端口**、在文档里大量出现，单独成类会大面积误报。
5. **放行面只限三类**（loopback / bind-all / CIDR）。若将来真有人拿某个私网地址当**通用示例**（对任何机器都不成立），它会命中 —— 应**登记例外**，不是放宽类。（本文档自己也踩过一次：讲解时的私网字面量被本类拦下，改用 `x` 占位。）
6. **脱敏闸门仍不扫源码**（`scripts/*.cjs`、`src/**/*.test.ts` 里的字面路径）—— 与 round-159 §六.6、round-160 §六.5 同源边界。
7. **本轮只收 round-160 §六.⑥ 的 IPv4 一支**：round-160 §六 的 ①~⑤、⑦~⑨ 仍开放（① 未跑产品侧构建与单测；② 锚点校验用近似 github-slugger；③ `#L<n>` 行号锚点不校验；④ `~/` 开头的目标不校验；⑤ 脱敏闸门不扫源码；⑦ 平台默认用户名仍会命中；⑧ 链接闸门不校验语义一致性）。
8. **本轮的判定线仍是我划的**：「内网 / Tailscale 主机地址算不算『标识本机』」这一步是我按 §5.4 判定线推的（**已向用户确认后才动手**）。若认为不该收，回退方式是**删掉闸门里那一个类** + 还原 2 行语料 —— 规范条文本身不需要改（判定线原文没变）。
