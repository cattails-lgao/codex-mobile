# round-98 · 状态色回归修复 + 暗色覆盖层退役

日期：2026-09-24 · 前置：round-97 收官（P0/P1/P2 全落地）；用户免审授权延续

本轮做两件事：①发现并修复 round-97 sweep 引入的**状态色可读性回归**；②完成 round-97 遗留的**暗色覆盖层退役**（268 个 raw 档位类清零）。

## 1. round-97 sweep 的状态色回归（修复 81 处，25 文件）

**发现**：抽查 `.composer-runtime-error` 的暗色覆盖时发现其亮色基线是 `border-alert bg-alert text-alert`——底、边、字同为 `#c62b2b`，文字完全不可读。溯源 git 历史：round-97 前是 `border-rose-200 bg-rose-50 text-rose-800`（浅玫瑰底横幅），sweep 的「状态色剥档位换 token」映射对**所有档位一视同仁**，把浅色状态底（`*-50/100/200`）也换成了实色状态底。

**排查**：审计脚本扫描「同色 bg+text」「hover:bg 同色 + hover:text 同色」组合并对 82b31ce2（round-97 前）逐处对照原值——**79 处全部实锤**，旧值全是浅色状态底（`bg-rose-50`×24、`bg-emerald-50`×14、`bg-amber-50`×13、`bg-rose-100`×8、`bg-amber-100`×7、`bg-emerald-100`×6、其余零星），无一误报。等值闸门当时没抓到它：这些横幅多为错误态、不在 145 个采样点内——「闸门范围」教训的又一形态。

**修复**：浅底 → 状态 token 透明度淡底（对齐 round-91「状态色 15% 淡底」口径）：
- bg：50 系 → `/10`，100 系 → `/15`，200 系 → `/25`
- border：200 → `/30`，300 → `/40`
- hover:bg 跟随同档位；`text-*` 保持 round-97 的 token 收敛（淡底上 alert 字对比度 ≈4.9:1 达 AA）

**过程教训（两次自伤）**：修复脚本 v1 按「NOW 文本前 30 字符」定位目标行——不同类共享相同 NOW 前缀（`composer-runtime-error` 与 `external-session-banner` 的 @apply 同前缀），导致替换错配；**回滚全部改动重来**。v2 改用 NOW 全文精确匹配 + 选择器消歧，剩余 12 处截断行用前缀匹配兜底 + 2 处 hover 残漏手工修。另：audit 的 WAS 对照按「选择器首次出现」匹配，同名选择器（`.directory-error` 在同文件有两个块）会取错，最后 1 处手工核实修复。

**防回归**：契约新增断言「状态色底与同色文字不共存（实色底上的文字必须是反色墨）」——扫描全 src 的 `bg-X`（实色，无透明度修饰）与同色 `text-X` 共存、以及 `hover:bg-X` + `hover:text-X`，契约 33 → **34 项**。

## 2. 暗色覆盖层退役（135 处规则剥离，净 -518 行）

round-97 后亮色基线已全部 token 化，且 token 走 `@theme inline` + 运行时变量——**token 工具类自动切主题**。因此暗色覆盖块的退役判据是「覆盖块删掉后，基线 token 的暗值是否接管正确」，逐块人工判读（round-97 明确不能 shade 映射）。

**判读结果**（style.css 117 块 + 组件 `:global(:root.dark)` 15 处编辑，合计 135 处规则）：

- **B 类（收敛删除，114 块）**：基线 token 已有同语义。暗色状态文字从 raw 档位收敛到状态 token（`emerald-300`→`--ok` #3ecf8e、`rose-300`→`--alert` #ff5c5c、`amber-300`→`--live` #f0a53a、`violet-300`→`--model`）；sky/blue（信息/链接语义）与 round-97 亮色决策一致地归入墨/线中性（登录链接、文件路径按钮、composio 预览等暗色不再特判蓝色）。
- **C 类（18 块）**：16 块是**死规则**——`header-git-*`（7）、`plan-card*`/`plan-step-*`（7）、`cmd-status-*`（3，模板里根本没有 `.cmd-status` 元素）系 round-91/93 组件重构后遗留，直接删；2 块活的（`skills-sync-device a`、`directory-marketplace-remove:hover`）删除后跟随基线（中性）。
- **安全细节**：部分块含非 raw 内容（`shadow-none`×2、`text-white`×6、`ring-1`、token 类、径向渐变）——**不能整块删**，脚本从 `@apply` 中只剥离 raw 档位类，剥空才删整块（98 整删 + 37 剥离保留）。

**过程坑**：剥离脚本第一版把 `{` 之后的内容删了但留下**选择器行**（含多行逗号组的前缀行），全站残留 ~95 处悬空选择器——CSS 容错会把悬空行与下一条规则的选择器合并成组，语义损坏且难察觉。用迭代清理脚本（悬空行 + 向上连带逗号前缀行，循环到稳定）修复，验证悬空 = 0、大括号配平 = 0、空块 = 0。

**防回归**：契约新增断言「暗色覆盖层 raw 档位清零」——`DARK_RAW_NS` 覆盖全 25 个色系 × 所有颜色属性前缀，用契约既有的逐字符栈式扫描的 dark 分类统计，契约 34 → **35 项**。
