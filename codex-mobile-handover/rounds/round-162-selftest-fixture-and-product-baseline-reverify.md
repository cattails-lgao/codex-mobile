## 二、① round-161 的自相矛盾：把地址从文档删掉、却写进了脚本

### 2.1 现象

round-161 的动作是：**新增「私网 / Tailscale 主机地址」类**，并把闸门扫出的 **2 处真实 tailnet 地址**从文档里删掉（换成 `<tailnet 地址>`）。当轮闸门读数是「违规 0 处」，看起来已闭合。

但把地址从**文档**里删掉，并不等于把它从**仓库**里删掉 —— 该地址**仍以字面量躺在 `scripts/check-handover-desensitization.cjs` 里**（round-161 次笔 `fa846b59` 新增的 `--selftest` 夹具表）：

```
148:    ['<该机 tailnet 地址>', 1],              // 原注释：Tailscale 段上界
162:    ['http://<该机 tailnet 地址>:4173', 1],  // URL 里的地址必须命中
```

### 2.2 根因

`--selftest` 的夹具是**照抄当时观测到的真实值**写的，而写入它的提交（`fa846b59`）**就在删除文档里同一字符串的提交（`a2d33790`）之后一笔**。也就是说：同一轮里，一处删、一处留，**两次动作都没有跨文件复核该字面量**。

后果是**两头都不成立**：

- 若该地址敏感 ⇒ round-161 的修复**没修掉**（地址仍在公开 fork 的 HEAD 里）；
- 若该地址不敏感 ⇒ 那 2 处文档改动就是**表演**。

### 2.3 严重度：真但与项目无关的「自伤」

需要如实说明：`100.64.0.0/10` 是 **CGNAT / Tailscale 段，公网不可路由**，它不是凭据、不是令牌 —— 知道它并不能连上那台机器（还须先在同一 tailnet 内）。所以这条**不是安全事件**，而是**一致性缺陷**：round-161 声称「该地址已从仓库移除」，而该声称**当时不成立**。

本轮的定位就是把这个**不成立的声称**变成成立的。

### 2.4 修复

`--selftest` 夹具表两处字面量 → `<合成地址>`（合成值，**仍落在 `100.64-127` 段内** ⇒ 断言值 `1` 不变、类仍必须命中，用例覆盖零损失）；同时把 148 行的注释由「Tailscale 段上界」改为「Tailscale 段内（合成夹具地址，非真实主机）」（合成值取段中位，不再是上界）。

改动共 **2 行字面量 + 1 行注释**，脚本 EOL（LF）与结构未动，`node --check` 通过。

### 2.5 验证

```
git grep "<该机 tailnet 地址>" HEAD   ⇒ 零命中（改前 2 处）
node scripts/check-handover-desensitization.cjs --selftest  ⇒ 自检通过：19 例
node scripts/check-handover-desensitization.cjs             ⇒ 违规 0 处 ｜ 例外 9 处（登记 6 条），12 类，退 0
```

### 2.6 本轮自己也被闸门拦了一次（第二次「闸门抓住作者」）

写这份文档时，为了把整改讲清楚，我把两个地址的**字面量**直接写进了 md ⇒ 脱敏闸门当场报 **违规 11 处**（本文档 6 处、总入口 2 处、台账 3 处）。这与 round-161 的「`10` 分支 bug 被自己文档里的 4 段示例自曝」**是同一形态** —— 闸门现在敏感到**能拦住它的作者**。

修法：md 里一律用语义占位（`<该机 tailnet 地址>` / `<合成地址>`），**字面量只留在脚本的 `--selftest` 表里**（闸门按定义只扫 `*.md`，脚本不在范围内）。修后违规 **0 处**。

顺带印证了 §五.6 的判断：**「闸门只扫 md」这条边界，正是「地址可以留在脚本里」这件事的根因**。
