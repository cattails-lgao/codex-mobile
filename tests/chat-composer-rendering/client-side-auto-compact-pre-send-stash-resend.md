### Client-side auto-compact: pre-send check + stash/resend (方案见 `codex-mobile-handover/sections/auto-compact-plan.md`)

#### Feature/Change Name
当线程剩余上下文占比 ≤ 发送前自动压缩阈值（设置项，默认 10%，0=关闭）时，发送消息先暂存并触发压缩，压缩完成后自动补发；暂存消息与 Queue 面板合并展示（带「发送前压缩上下文」徽标），刷新后从 localStorage 恢复并继续「检查用量 → 压缩（如需）→ 补发」。

#### Prerequisites/Setup
1. Dev server 运行中（`pnpm run dev --host 127.0.0.1 --port 4173`）
2. 至少一个已有会话（有上下文用量数据的线程）
3. 明暗主题均可用

#### Steps
1. 打开设置面板 → General → 「发送前自动压缩」，确认默认值为 `10%`，下拉含 Off/5%/10%/15%/20%/25%
2. 选择一个上下文用量较高（剩余 ≤10%）的线程，在输入框输入一条消息并发送
3. 确认消息不立即发出：输入框上方面板出现该消息行，行尾带「发送前压缩上下文」徽标；消息流出现「正在压缩上下文…」pending 行
4. 等待压缩完成：pending 行变为「Context compacted」，暂存行自动消失，消息自动发出（出现新 turn）
5. 压缩期间再发送第二条消息，确认第二条也进入暂存区，压缩完成后两条按序补发
6. 刷新页面：确认暂存中的消息仍在面板中（localStorage 恢复），线程空闲后自动继续压缩并补发
7. 对暂存消息点击「Steer」：确认立即发送（不再等待压缩）
8. 对暂存消息点击「Edit」：确认回填输入框并移除暂存行；重新发送后再次进入暂存流程
9. 对暂存消息点击删除：确认行消失且 localStorage 同步移除
10. 将阈值改为 `Off`（0），在高用量线程发送消息：确认直接发送、不再暂存（退回服务端自动压缩）
11. 切到暗色主题，重复步骤 2-4：确认面板/徽标/pending 行在暗色下可读
12. 将阈值改为 `15%` 并刷新页面：确认设置仍为 `15%`；再改回默认 `10%`

#### Expected Results
- 阈值内发送：消息先暂存（面板可见 + localStorage 持久化），压缩完成后自动补发，消息不丢
- 阈值 0：完全跳过预检，直接发送
- 用量高于阈值：直接发送，无暂存
- 压缩中再发送：进入暂存区，压缩完成后按序补发
- 刷新恢复：暂存消息不丢，线程空闲且用量同步后自动继续压缩/补发
- 暂存消息支持 Edit/Delete/Steer，不参与拖拽排序（顺序固定置前）
- 自动压缩阈值刷新后保持；非法或负值不会产生负阈值
- 明暗主题下面板、徽标、按钮均正常显示

#### Rollback/Cleanup
- 测试产生的暂存消息可通过面板删除或等压缩完成后自动清空
- 设置项可在设置面板改回默认 10%
- 删除不需要的临时线程（`thread/delete`）
